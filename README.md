# MMRemover

**Minecraft Malware Remover** — программа для автоматической очистки вирусов с плагинов Minecraft.

**Домены малвари для бана на хостинге:** актуальный список — [b0b0b0.dev/vb.json](https://b0b0b0.dev/vb.json) (JSON, можно парсить автоматически). Часть доменов уже мертва, но резать на DNS всё равно имеет смысл.

## Удаляет

- Hostflow
- Артёмка
- bStats.jar
- PluginMetrics.jar
- aph
- ChbkHack
- ruBstatsHack (`ru/bstats`, `me/bstats` + `bstats.xyz`)
- **SystemMetrics** (`panel.bstats.co`)
- **KtoDropper** (`lib/metrics/Boot`, `META-INF/m.bin`, `kto.ultimatebox.fun`)

## SystemMetrics — чаморы и `panel.bstats.co`

В JAR вшивают фейковый «bStats»: метод `SystemMetrics` качает payload с **`panel.bstats.co`** (это **не** настоящий bStats) и дергает `onEnableInj`. MMRemover это находит и вырезает.

Но есть нюанс, о котором стоит знать заранее.

Вирус **SystemMetrics** (`panel.bstats.co`) встраивается в главный класс плагина — например, `DecentHologramsPlugin.onEnable()` вызывает `this.SystemMetrics(this)`, метод качает инжект с **`panel.bstats.co`** и дергает `onEnableInj`. **ЧАМОРЫ**, которые пихают именно эту малварь в leak-сборки, **не смогли в ремапинге Paper** — и **уничтожили плагин изначально**, ещё до любой очистки: в тот же JAR, куда воткнули `SystemMetrics`, они положили **165 пустых NMS-классов** (`.class` на 0 байт) под `v1_20_R4`, `v1_21_R*` и `paper_v1_21_*`. Paper 1.21.x при старте падает на ремапе (`ClickableHologramRenderer` → `ArrayIndexOutOfBoundsException: length 0`) — **DecentHolograms с этим вирусом не запустится ни с малварью, ни после вырезки**, пока NMS не подставить из другого целого JAR.

Итого:

| Что | MMRemover |
|-----|-----------|
| Бэкдор `SystemMetrics` / `panel.bstats.co` | вырезает |
| Пустые NMS-классы (порча сборки чаморами) | не чинит — байтов нет |

Домен **`panel.bstats.co`** имеет смысл резать на хостинге/DNS — пока чаморы не разнесли ещё плагины.

## KtoDropper — «метрика» `lib/metrics/Boot`

Притворяется метрикой. Один и тот же дроппер вшит в каждый jar папки `plugins`. Какой плагин загрузится первым, тот и поднимает агента. Остальные видят `kto.started=1` и молчат. Вычистить один jar мало: чистится вся папка, потом рестарт.

### Что лежит в jar

- `lib/metrics/Boot.class`, `Boot$1.class` (поток), `Boot$MemLoader.class`. Пакет могут переименовать, состав тот же.
- `META-INF/m.bin`. Это не конфиг плагина и не адрес Minecraft-сервера. IP в jar открытым текстом нет.
- В `<clinit>` класса плагина, сразу перед `return`:

```
invokestatic lib/metrics/Boot.start()V
```

На пачке из 91 jar заражены 90, чистый только `DeadDontCrystall-1.jar`. Хеш `Boot.class` у всех один. `m.bin` у каждого jar свой. Пустых NMS, как у SystemMetrics, нет.

### Что делает `Boot.start()`

1. `AtomicBoolean`: в этой JVM повторно не стартует. Демон-тред с именем `metrics-worker` зовёт `load()`.
2. Выход, если свойство `kto.started` уже `1`.
3. Читает `META-INF/m.bin`. Короче 40 байт — выход.
4. Ключ: SHA-256 от UTF-8 `K7m2Qp9x` + `R4t8Vb1n` + `L6s3Wz5c` и первых 16 байт блоба. `AES/GCM/NoPadding`, тег 128 бит, IV = байты 16–28, шифртекст с 28-го байта.
5. Расшифровка — пять строк через `\n`: URL, хост, порт, токен, метка. Метку сам `Boot` не читает. Порт обязан быть 1–65535, URL и хост не пустые.
6. Под локом на `System.getProperties`. Уже стоит `kto.boot=1` — другой плагин качает, выход. Иначе ставит `kto.boot=1`.
7. Качает URL, 3 попытки. Пауза 4 с, потом 7 с. Годится `file:` и HTTP: таймауты 20/60 с, редиректы включены, юзер-агент Chrome 124, берёт только ответ 2xx. Потолок 64 МБ. Коротже 4096 байт — выкинуть.
8. Jar распаковывается в память. На диск `core.jar` не пишется. Нет записи `kto/Core.class` — выход.
9. Пишет свойства `kto.host`, `kto.port`, `kto.token`, `kto.embedded=1`.
10. `MemLoader` делает `defineClass` из этих байт. `Class.forName("kto.Core")`, потом `start()`, а если метода нет — `main(String[])`.
11. `kto.started` ставит уже `kto.Core`. Не поставил — `Boot` снимает `kto.boot`, и следующий заражённый плагин в той же JVM пробует снова.

На этой пачке в блобе: `https://kto.ultimatebox.fun/core.jar`, хост `202.181.188.121`, порт `20011`, метка `ServerCore`. Панель ту же метку пишет в `pluginName`, агентов принимает на `20011`, сама висит на `8080`.

`kto.Core` в jar нет. Это второй этап, только в куче процесса. Шелл, архив Telegram и запись `authorized_keys` в байтах `Boot` не лежат: это команды панели уже подключённому агенту.

### Пока агент ещё не сел

| След | Где смотреть |
|------|----------------|
| `META-INF/m.bin` | запись внутри jar |
| `kto.host`, `kto.port`, `kto.token`, `kto.embedded`, `kto.started`, `kto.boot`, `kto.Core` | строки класса дроппера |
| в одном классе вместе `META-INF/m.bin`, `AES/GCM`, `HttpURLConnection` и `defineClass` или `Class.forName` | тот же класс, если строки переименуют |
| `invokestatic …start()V` в конце `<clinit>` | класс плагина |
| тред `metrics-worker` | дамп потоков живого сервера |
| свойства `kto.host` / `kto.port` / `kto.token` / `kto.embedded` / `kto.boot` / `kto.started` | `jcmd <pid> VM.system_properties` |
| исходящий TCP на `202.181.188.121:20011` | `ss -tpn`, tcpdump |
| GET `https://kto.ultimatebox.fun/core.jar`, юзер-агент Chrome | тот же tcpdump |

Рестарт без чистки jar поднимает дроппер заново. Чистка без рестарта оставляет `kto.Core` в памяти до остановки `java`.

Резать на DNS и файрволе: `kto.ultimatebox.fun`, `202.181.188.121`, порт `20011`.

### Что чистит MMRemover

Имя класса не зашито. Дроппер узнаётся по строкам `kto.*` выше. Вторая ветка — структурная, из той же таблицы. Имя берётся из самого class-файла, вызов `start()V` этого класса затирается.

Вызов — три байта `invokestatic`, стек не трогает. На их место три `nop`. Остальной `<clinit>` не переписывается: у WorldEdit остаётся `LogManagerCompat.getLogger()`, у ProtocolLib его `ReportType`, у LPX свой DES. Класс целиком через ASM не гоняется, иначе большой плагин можно убить фреймами.

| Что | MMRemover |
|-----|-----------|
| `META-INF/m.bin` и классы дроппера (`Boot` и `Boot$…`, как бы пакет ни назвали) | удаляет |
| `invokestatic …start()V` | три `nop`, остальной метод на месте |
| Чужой шифр рядом (LPX, NormalSpit) | не трогает |
| Метод назвали не `start` или у вызова появились аргументы | jar не переписывает, в логе `ktoDropperUnsafe` |

## ru/bstats — малварь `api-bstats.online` (adod_bstats)

**Не путать с настоящим [bStats](https://bstats.org)** (`org.bstats`, метрики на `bstats.org`). Это отдельная семья бэкдоров, маскирующихся под bStats.

### Названия / следы в коде

| Как встречается | Что это |
|-----------------|---------|
| **adod_bstats** / **bstats.jar** | Отдельный «плагин» `name: bStats`, main `ru.bstats.Bootstrap` |
| **`ru/bstats/`** | Вшито в leak-плагины (`Metrics.load()` в `onEnable`) |
| **`me/bstats/`** | Вариант той же семьи (`MetricsConfig` → `bstats.xyz`, `adod_bstats.jar`) |
| **C2** | `http://api-bstats.online`, зеркала через `/domain.list` |
| **Автор (подписи)** | @adodovsky, NULLUDP, файл `крякерыпрочитайте.alexey` |

User-Agent на C2: `Java/forchhh-core`. Ключ шифрования payload: `Make bstats great again!` + AES-GCM.

### Как устроено (два слоя)

**Слой 1 — видимый JAR** (`bstats.jar`, ~900 КБ):

- `plugin.yml`: `name: bStats`, `main: ru.bstats.Bootstrap`
- `data/1` — зашифрованный ZIP с payload (~850 КБ)
- `ru.bstats.Bootstrap` — читает `data/1`, расшифровывает, грузит классы в память (`InMemoryLoader`)
- Куча мусорных классов с рандомными пакетами — шум для анализа

**Слой 2 — payload в памяти** (`ru.bstats.RemoteBootstrap`, `ru.bstats.a`, …):

- Ищет последний **enabled**-плагин через Bukkit API
- Вешается на него как «хост»
- Глушит `System.out` / `System.err` (консоль сервера «тихая»)
- Копирует `крякерыпрочитайте.alexey` в `getDataFolder()` плагина
- Через вшитый **ASM** патчит **другие `.jar` в `plugins/`** на диске (персистентность)
- Поддержка **Bukkit**, **BungeeCord**, **Velocity**

Настоящего `org/bstats/` в этих JAR **нет**.

### Что делает на сервере (не на Windows)

| Действие | Описание |
|----------|----------|
| Регистрация на C2 | POST JSON: `id`, `owner`, `platform`, `ip`, `port`, `is_pc` |
| Опрос команд | `poll` / `update` — ботнет, не «метрики» |
| `cmd` / `shell` | На Windows: `cmd /c …` (только пока крутится `java.exe`) |
| `mc` | Команды консоли Minecraft |
| `download` | Скачать файл на диск сервера по URL |
| `upload` | Отправить **конкретный** файл на C2 (hex), не автоматически |
| Эксфиль | Список **имён** файлов в папке, куски `logs/latest.log` — **не** заливка всей сборки |

**Не** вирус Windows: нет автозагрузки, реестра, служб. Работает только внутри процесса сервера. Удалил папку сервера — всё умерло.

### Декой в коде (можно игнорировать)

В `static {}` и константах — фейковые URL (`api.metrics.example.com`, `127.0.0.1`, китайские «пугалки» про Интерпол), неиспользуемые `@uuid`-строки. Нужны, чтобы отвлечь grep при реверсе. Реальный C2 — только `api-bstats.online` в `ru.bstats.d.a`.

### Вшитый вариант (`ru/bstats`, `me/bstats` внутри leak-плагина)

Отдельно от `bstats.jar`-дроппера: малварь сидит **внутри** чужого JAR.

- В `onEnable` вызывается `Metrics.load()` или `MetricsBase.configure()`
- C2: **`api-bstats.online`**, **`bstats.xyz`**
- `InternalService` разносит заразу по **другим `.jar` в `plugins/`**
- Вшивает **asm.jar + asm-tree.jar** → в ZIP появляются **дубли** (`module-info.class` ×3)

### Как чистит MMRemover (`ruBstatsHack`)

- Дедуп записей в ZIP (чтобы не осталась пустышка из одного ASM ~120 КБ вместо ~700 КБ)
- Вырезка `ru/bstats/*`, `me/bstats/*`, мусорного `org/objectweb/asm/`
- Удаление вызовов `Metrics.load` / `MetricsBase.configure` из главного класса
- **Плагин остаётся целым**

**`bstats.jar`** с `ru.bstats.Bootstrap` и `data/1` — это **отдельный дроппер**, не leak-плагин. Его **удаляют из `plugins/` целиком**; «починить» байткодом в рабочий плагин нельзя.

## Требования

**Java 25** — нужна только чтобы запустить MMRemover на своём компе. Ставится один раз по [инструкции ниже](#шаг-3-установи-java-25).

## Использование

1. Запустите программу — при первом запуске выберите язык.
2. Закиньте заражённые плагины в окно или в папку `input`.
3. Нажмите **НАЧАТЬ ОЧИСТКУ**.
4. Заберите очищенные плагины из папки `out` или из правого окна.

Консоль показывает ход очистки. Кнопки под ней открывают/очищают `input`, `out` и консоль.

## Запуск

Пошагово внизу: [Как скачать и запустить (Windows)](#как-скачать-и-запустить-windows).

Кратко: на рабочем столе папка **`MMRemover`**, внутри — **`start.bat`** и jar. Дважды клик по **`start.bat`** (не по jar).

## Инспектор

**Лупа в заголовке каждого окна** (слева — заражённые, справа — `out`). **Только смотрит** — плагины не трогает и не чистит.

### Зачем

Перед очисткой можно быстро проверить, что в JAR вообще есть. Или глянуть уже очищенный файл в `out`, не запуская на сервере.

### Как пользоваться

1. Положите `.jar` в нужное окно (`input` слева или `out` справа).
2. **Один файл** — кликните по нему в списке и нажмите лупу в заголовке этого окна.
3. **Все файлы в окне** — ничего не выделяйте, нажмите лупу.
4. Подождите — откроется отчёт. Слева список, справа подробности.

### Что означают метки

| Метка | Значение |
|-------|----------|
| **[!]** | Нашли вирус или явно вредоносные адреса — лучше не ставить на сервер, сначала очистить |
| **[?]** | Что-то непонятное, не похоже на вирус, но и не из «белого списка» — на свой страх и риск |
| **[+]** | Подозрений нет |

### Что показывает отчёт

- **Обзор** — сколько плагинов проверили, у скольких есть проблемы, кратко по каждому файлу.
- **По каждому плагину** — нашёлся ли вирус, откуда тянутся плохие ссылки, есть ли что-то странное.
- Описание из `plugin.yml` (название, автор, главный класс) — чтобы понять, что это за плагин.

### Важно

- Инспектор **не удаляет** вирус. Для очистки — кнопка **«Начать очистку»**.
- Результат — это подсказка, не приговор. Легитимные плагины иногда попадают в «сомнительные» из-за ссылок в коде (документация, картинки, API). Если плагин с официального сайта и метка **[+]** — обычно всё ок.
- Если стоит **[!]** — не игнорируйте: прогоните через очистку или выкиньте JAR.

## Как скачать и запустить (Windows)

Если на сервере малварь в плагинах — делай **по порядку**, не перескакивай.  
Всё делаем **на рабочем столе** — он прямо перед тобой, в `C:\...` лезть не надо.

### Шаг 1. Папка на рабочем столе

1. Смотри на **рабочий стол** (где иконки игр, браузера и т.д.)
2. **Правой кнопкой** по пустому месту → **Создать** → **Папку**
3. Назови папку **`MMRemover`**
4. **Дважды кликни** по ней — откроется пустое окно. **Не закрывай** — сюда кладём файлы

### Шаг 2. Скачай **два файла** в эту папку

| Файл | Где скачать | Зачем |
|------|-------------|--------|
| **`MMRemover-2.xx.jar`** | [black-minecraft.com/resources/6091](https://black-minecraft.com/resources/6091/) | Сама программа (xx — номер версии с сайта) |
| **`start.bat`** | [**скачать запускатор**](https://github.com/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0/MMRemover/blob/main/start.bat) | Проверяет Java и открывает MMRemover |

**Запускатор обязателен.** Jar без `start.bat` — половина дела. Ссылка на bat:  
https://github.com/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0/MMRemover/blob/main/start.bat  
Откроется страница GitHub → справа **Download raw file** (или **Скачать**) → сохрани в папку **`MMRemover`** на рабочем столе. Имя файла должно быть **`start.bat`**, не `start.bat.txt`.

Положи **оба** файла **в открытую папку `MMRemover` на рабочем столе**.

Файлы часто падают в **«Загрузки»**. Тогда: открой **Загрузки**, выдели оба файла, **перетащи** мышкой в окно папки **`MMRemover`** на рабочем столе.

Должно получиться так:

```
Рабочий стол
  └── MMRemover
        MMRemover-2.xx.jar
        start.bat
```

### Шаг 3. Установи Java 25

1. Открой: **https://adoptium.net/temurin/releases/?version=25**
2. **JDK 25** → **Windows** → **x64** → скачай `.msi` и установи
3. При установке **обязательно** включи:
   - **Set JAVA_HOME variable**
   - **Add to PATH** (добавить в PATH)
4. **Перезагрузи комп** или закрой все окна и открой заново

`start.bat` сам проверит Java. Если её нет — напишет, что делать, и даст ссылку на Adoptium.

### Шаг 4. Запусти программу

1. Снова открой на рабочем столе папку **`MMRemover`**
2. **Двойной клик** по **`start.bat`** (не по jar!)
3. Откроется окно MMRemover
4. Первый раз — выбери язык (RU / EN)

### Шаг 5. Почисти плагины

1. Скопируй **подозрительные** `.jar` с сервера в папку **`input`**  
   (появится **на рабочем столе**, внутри `MMRemover`, рядом с `start.bat`) **или** перетащи их в **левое** окно программы
2. Нажми **«НАЧАТЬ ОЧИСТКУ»**
3. Дождись конца в консоли внизу
4. Забери файлы из **`out`** (там же, на рабочем столе в `MMRemover`) или из **правого** окна
5. **На сервер ставь только из `out`**, старые из `plugins` — в мусорку

### Если что-то пошло не так

| Что пишет / что случилось | Что делать |
|---------------------------|------------|
| **Java не найдена** | Переустанови Adoptium, галочки PATH и JAVA_HOME, перезагрузка |
| **jar не найден** | `MMRemover-*.jar` и `start.bat` должны лежать **в одной папке на рабочем столе** |
| Скачал только jar, без bat | [Скачай запускатор `start.bat`](https://github.com/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0/MMRemover/blob/main/start.bat) → **Download raw file**, в папку **`MMRemover`** |
| Куча `'...' is not recognized as internal or external command` при запуске bat | **Сломанный `start.bat`**: скачал как `start.bat.txt`, открыл в Блокноте и сохранил с не той кодировкой, или скопировал текст вручную. **Удали** старый bat → [скачай заново Raw](https://github.com/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0/MMRemover/blob/main/start.bat) → имя строго **`start.bat`**, в одной папке с jar |
| Файлы в «Загрузках», программа не видит jar | Перетащи оба файла в папку **`MMRemover`** на рабочем столе |
| Плагин после очистки не работает | Так бывает. Скачай плагин **из надёжного источника** — **не** с неофициальных сайтов. Если плагин **важный**, а нормальную копию **не достать** — напиши мне в [Телеграм](https://t.me/b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0b0) |
